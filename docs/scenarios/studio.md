# 场景：5 人设计工作室经营分析

> 你是一家设计工作室的合伙人。核心团队 5 人（设计总监 + 3 名设计师 + 视觉设计），
> 另有项目管理、客户执行、行政和 2 名兼职，一共 10 个人；手上有 2026 年的四张表：
> 员工、项目（40 个）、报销（60 笔）、考勤（90 条）。
> 目标：一次把「项目营收 / 员工绩效 / 费用报销 / 考勤」四条线看清楚——
> 谁在赚钱、哪单在亏、钱花在哪、人累不累。

**对 AI 说**：「用 `studio.xlsx` 的四张表算项目毛利（人力成本按时薪折算）、列出亏损项目和
负责人产值，再统计报销结构与考勤加班，最后出一张月度签约趋势图。口径写进 notes。」

**数据源**：[`../../examples/data/studio.xlsx`](../../examples/data/studio.xlsx)，四个工作表
（`员工` / `项目` / `报销` / `考勤`），由 `make examples-data` 用固定随机种子生成，结果可复现。
本场景**全程用 DuckDB 引擎**（`--engine duckdb`），顺带验证它与默认 SQLite 的行为一致。

## 先定口径（跳过这步，后面的数字都会吵起来）

| 指标 | 本场景的定义 | 为什么这么定 |
|------|-------------|-------------|
| 时薪 | `月薪 ÷ 176`（22 天 × 8 小时） | 固定口径才能横向比较；兼职也按月薪折算 |
| 人力成本 | `投入工时 × 时薪` | 项目表里有「投入工时」，员工表里有月薪，两张表 JOIN 出来 |
| 直接费用 | 报销里**非驳回**（已批 + 待批）且归属本项目的金额 | 待批也是已发生的支出；驳回不算 |
| 毛利 | `合同金额 − 人力成本 − 直接费用` | 不摊行政/房租（没有这些数据），所以叫「项目毛利」而不是净利 |
| 考勤周期 | 2026-07 的 9 个工作日 | 90 条 = 9 天 × 10 人，只能当「最近两周的出勤切片」看 |

## ★★ 毛利：把人力成本算进去

合同额只是「营业额」。工作室真正的经营指标是**毛利**，而毛利要靠 JOIN 算出来：

```bash
dtool query --engine duckdb --rows --sql "
  WITH 费用 AS (
    SELECT 项目ID, SUM(金额) AS 直接费用 FROM 报销 WHERE 状态 <> '驳回' GROUP BY 1
  )
  SELECT ROUND(SUM(p.合同金额)/10000,1) AS 合同额万,
         ROUND(SUM(p.投入工时 * e.月薪/176.0)/10000,1) AS 人力成本万,
         ROUND(COALESCE(SUM(f.直接费用),0)/10000,1) AS 直接费用万,
         ROUND((SUM(p.合同金额) - SUM(p.投入工时 * e.月薪/176.0)
                - COALESCE(SUM(f.直接费用),0))/10000,1) AS 毛利万,
         ROUND(100.0*(SUM(p.合同金额) - SUM(p.投入工时 * e.月薪/176.0)
                - COALESCE(SUM(f.直接费用),0))/SUM(p.合同金额),1) AS 毛利率
  FROM 项目 p
  JOIN 员工 e ON p.负责人ID = e.员工ID
  LEFT JOIN 费用 f ON f.项目ID = p.项目ID"
```

```json
{"合同额万":401.6,"人力成本万":153.2,"直接费用万":8.1,"毛利万":240.3,"毛利率":59.8}
```

**读法**：401.6 万签约额，人力成本 153.2 万（38%），直接费用只有 8.1 万，毛利率 59.8%。
设计工作室的成本结构就是「人」——所以任何「多干活不加钱」的动作，都是直接扣毛利。

## ★★ 亏损项目：谁把利润做没了

```bash
dtool query --engine duckdb --rows --sql "
  WITH 费用 AS (
    SELECT 项目ID, SUM(金额) AS 直接费用 FROM 报销 WHERE 状态 <> '驳回' GROUP BY 1
  )
  SELECT p.项目ID, p.项目类型, p.合同金额, p.投入工时,
         ROUND(p.投入工时 * e.月薪/176.0) AS 人力成本,
         ROUND(p.合同金额 - p.投入工时 * e.月薪/176.0 - COALESCE(f.直接费用,0)) AS 毛利,
         p.状态
  FROM 项目 p
  JOIN 员工 e ON p.负责人ID = e.员工ID
  LEFT JOIN 费用 f ON f.项目ID = p.项目ID
  ORDER BY 毛利 ASC LIMIT 5"
```

```json
{"项目ID":"PRJ2026-023","项目类型":"包装设计","合同金额":30000,"投入工时":352,"人力成本":90000,"毛利":-60000,"状态":"已完成"}
{"项目ID":"PRJ2026-009","项目类型":"包装设计","合同金额":40000,"投入工时":200,"人力成本":51136,"毛利":-13304,"状态":"已完成"}
{"项目ID":"PRJ2026-033","项目类型":"包装设计","合同金额":42000,"投入工时":220,"人力成本":35000,"毛利":255,"状态":"已完成"}
{"项目ID":"PRJ2026-027","项目类型":"插画","合同金额":17000,"投入工时":90,"人力成本":11250,"毛利":5272,"状态":"已完成"}
{"项目ID":"PRJ2026-006","项目类型":"插画","合同金额":24000,"投入工时":80,"人力成本":12727,"毛利":10573,"状态":"已完成"}
```

**为什么亏**：`PRJ2026-023` 合同 3 万、投入 352 小时——按 176 小时/月算等于两个人干一个月，
人力成本 9 万。再看是谁负责的：

```bash
dtool query --engine duckdb --rows --sql "
  SELECT p.项目ID, p.合同金额, p.投入工时, e.姓名 AS 负责人, e.月薪
  FROM 项目 p JOIN 员工 e ON p.负责人ID = e.员工ID
  WHERE p.合同金额 < p.投入工时 * e.月薪/176.0"
```

```json
{"项目ID":"PRJ2026-023","合同金额":30000,"投入工时":352,"负责人":"沈一","月薪":45000}
{"项目ID":"PRJ2026-009","合同金额":40000,"投入工时":200,"负责人":"沈一","月薪":45000}
```

两单都在**时薪最高（255.7 元/小时）的总监**名下。这就是工作室最常见的隐性亏损：
**低价单配了最贵的人**。处置不是「让总监别干活」，而是给低价单定一条工时上限，或换成时薪
更低的执行者（设计师 125 元/小时，相当于成本直接打对折）。

## ★★ 员工绩效：产值是月薪的几倍

```bash
dtool query --engine duckdb --rows --sql "
  SELECT e.姓名, e.岗位, COUNT(*) AS 项目数,
         ROUND(SUM(p.合同金额)/10000,1) AS 合同额万, SUM(p.投入工时) AS 工时,
         ROUND(SUM(p.合同金额)/e.月薪,1) AS 产值月薪倍数
  FROM 项目 p JOIN 员工 e ON p.负责人ID = e.员工ID
  GROUP BY e.姓名, e.岗位, e.月薪 ORDER BY 合同额万 DESC"
```

## 结论怎么写（可直接改成周报）

1. **收入结构**：空间展陈贡献四成签约额（169.2 万 / 401.6 万），包装设计单量最多（12 单）
   但单价最低（5.2 万），是最该做「标准化报价 + 改稿收费」的一类。
2. **毛利**：整体毛利率 59.8%，人力成本占签约额 38%——省人不如提价，也不如减少无效改稿。
3. **亏损**：两单亏损合计 7.3 万，都在时薪最高的总监名下；建议给低价单设工时上限，
   并把执行换成时薪更低的层级。
4. **人**：方竹产值最高且最饱和（15 单 / 3732 小时 / 加班 17 小时），是产能瓶颈；
   陆遥「加班 20 小时 + 请假 3 天」需要谈一次负载。
5. **钱**：外包占报销 53%、无项目归属 4.26 万（管理费），所以 59.8% 的毛利率对净利是**乐观估计**；
   待批 1.7 万要在月末清掉。

## 常见坑

- **别用「合同金额」当收入**：没有回款数据，这里是签约额；毛利率也不含房租/行政。
- **时薪口径要写死**：`月薪/176` 是本场景的约定，换成 173.3（月均工时）结论会小幅变化，
  但排序不变。写进 `--notes`，下次才能对齐。
- **报销要排除驳回**：`WHERE 状态 <> '驳回'`；「待批」算不算成本，要和财务口径一致。
- **考勤和项目周期不是同一个时间段**：90 条只覆盖 2026-07 的 9 个工作日，不能拿它去乘全年。
- **`FILTER (WHERE ...)` 是 DuckDB 语法**：换 SQLite 要用 `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`；
  反过来 SQLite 不支持的 `QUALIFY` / `ROLLUP`，加 `--engine duckdb` 就能用。
- **中文列名可以直接写**（`SELECT 区域, SUM(金额) ...`），含空格时才需要双引号。
- **强隐私下 `--rows` 会被拒（code 6）**：本文的数字是文档作者在 `privacy: normal` 下取的；
  Agent 侧应只交付产物路径，不复述取值。

```bash
# 0) 准备
for s in 员工 项目 报销 考勤; do dtool convert --input studio.xlsx --sheet "$s" --name "$s"; done

# 1) 营收
dtool query --engine duckdb --sql "SELECT 项目类型, COUNT(*) 项目数, ROUND(SUM(合同金额)/10000,1) 合同额万 FROM 项目 GROUP BY 1 ORDER BY 2 DESC"
dtool query --engine duckdb --sql "SELECT 状态, COUNT(*) 项目数, ROUND(SUM(合同金额)/10000,1) 合同额万 FROM 项目 GROUP BY 1"
dtool query --engine duckdb --sql "SELECT 客户, ROUND(SUM(合同金额)/10000,1) 合同额万 FROM 项目 GROUP BY 1 ORDER BY 2 DESC LIMIT 5"

# 2) 毛利与亏损（人力成本 = 工时 × 月薪/176）
dtool query --engine duckdb --sql "WITH 费用 AS (SELECT 项目ID, SUM(金额) AS 直接费用 FROM 报销 WHERE 状态 <> '驳回' GROUP BY 1) SELECT ROUND(SUM(p.合同金额)/10000,1) 合同额万, ROUND(SUM(p.投入工时*e.月薪/176.0)/10000,1) 人力成本万, ROUND((SUM(p.合同金额)-SUM(p.投入工时*e.月薪/176.0)-COALESCE(SUM(f.直接费用),0))/10000,1) 毛利万 FROM 项目 p JOIN 员工 e ON p.负责人ID=e.员工ID LEFT JOIN 费用 f ON f.项目ID=p.项目ID"

# 3) 绩效
dtool query --engine duckdb --sql "SELECT e.姓名, COUNT(*) 项目数, ROUND(SUM(p.合同金额)/10000,1) 合同额万, ROUND(SUM(p.合同金额)/e.月薪,1) 产值月薪倍数 FROM 项目 p JOIN 员工 e ON p.负责人ID=e.员工ID GROUP BY 1,e.月薪 ORDER BY 3 DESC"

# 4) 报销
dtool query --engine duckdb --sql "SELECT 费用类型, COUNT(*) 笔数, ROUND(SUM(金额)) 金额 FROM 报销 GROUP BY 1 ORDER BY 3 DESC"
dtool query --engine duckdb --sql "SELECT 状态, COUNT(*) 笔数 FROM 报销 GROUP BY 1"

# 5) 考勤
dtool query --engine duckdb --sql "SELECT 出勤类型, COUNT(*) 人次, SUM(加班工时) 加班 FROM 考勤 GROUP BY 1"
dtool query --engine duckdb --sql "SELECT e.姓名, SUM(a.加班工时) 加班小时 FROM 考勤 a JOIN 员工 e ON a.员工ID=e.员工ID GROUP BY 1 ORDER BY 2 DESC LIMIT 5"

# 6) 一条龙 + 导出
dtool pipeline --input dataset:项目 --engine duckdb --sql "SELECT substr(开始日期,1,7) 月份, ROUND(SUM(合同金额)/10000,1) 合同额万 FROM data GROUP BY 1 ORDER BY 1" --chart line --x 月份 --y 合同额万 --output out/月度签约.png
```
