# 场景：HR / 人事

> 你是这家公司的人事负责人。手上是 `hr.xlsx` 的 `员工` 表：60 人，含工号（`00101` 起，
> 有前导零）、姓名、部门、职级、月薪、入职日期、绩效（2026 年入职者为空）。
> 目标：算清**人力成本、职级结构、待评估名单**，并给出能直接进周会的一张表。

**对 AI 说**：「汇总 `hr.xlsx` 各部门人数与平均月薪并出饼图，导出绩效为空的人员名单，
再做部门 × 职级的透视和各部门薪酬 Top2。」

**数据源**：[`../../examples/data/hr.xlsx`](../../examples/data/hr.xlsx)（工作表 `员工`）。

## 先定口径

| 指标 | 本场景定义 | 为什么 |
|------|-----------|--------|
| 人力成本 | `SUM(月薪)`，按月 | 本数据只有月薪，没有奖金/社保；对外报「人力成本」要说明口径 |
| 平均月薪 | `AVG(月薪)`，**按部门人数加权**（不是部门平均的平均） | 直接 `AVG(AVG())` 会被小部门拉偏 |
| 待评估 | `绩效 IS NULL` | 本数据里等于「2026 年入职、还没到考核周期」 |
| 职级带 | 初级 P3–P4 / 中级 P5–P6 / 高级 P7 | 汇报时简化为三档，避免 5 行表格 |

## 准备

```bash
mkdir -p /tmp/hr && cd /tmp/hr
cp /path/to/dtool/examples/data/hr.xlsx .
dtool convert --input hr.xlsx --sheet 员工 --name hr
dtool datasets show hr        # 工号是 string（前导零保住了）
```

> 下文用 `--rows` 展示取值（**仅 `privacy: normal` 可用**）；默认强隐私去掉它即可。

## ★ 各部门人数与薪酬

```bash
dtool query --rows --sql "
  SELECT 部门, COUNT(*) AS 人数, ROUND(AVG(月薪)) AS 平均月薪, ROUND(SUM(月薪)) AS 月薪总额
  FROM hr GROUP BY 1 ORDER BY 人数 DESC"
```

```json
{"部门":"销售部","人数":15,"平均月薪":24467,"月薪总额":367000}
{"部门":"技术部","人数":14,"平均月薪":26721,"月薪总额":374100}
{"部门":"财务部","人数":9,"平均月薪":24289,"月薪总额":218600}
{"部门":"产品部","人数":9,"平均月薪":22144,"月薪总额":199300}
{"部门":"人事部","人数":7,"平均月薪":21886,"月薪总额":153200}
{"部门":"市场部","人数":6,"平均月薪":20300,"月薪总额":121800}
```

**读法**：全公司月薪合计 **143.4 万**（年化 1721 万）。技术部人数第二但总额第一
（37.4 万），销售部人数最多（15 人）总额略低——**技术是成本中心，销售是人数中心**。
市场部只有 6 人却平均 2.03 万，是「小而贵」的结构。

## ★ 职级分布：有没有「职级通胀」

```bash
dtool query --rows --sql "
  SELECT 职级, COUNT(*) AS 人数, ROUND(AVG(月薪)) AS 平均月薪
  FROM hr GROUP BY 1 ORDER BY 1"
```

```json
{"职级":"P3","人数":8,"平均月薪":10625}
{"职级":"P4","人数":17,"平均月薪":16112}
{"职级":"P5","人数":19,"平均月薪":22711}
{"职级":"P6","人数":5,"平均月薪":32160}
{"职级":"P7","人数":11,"平均月薪":43891}
```

**读法**：P7 有 11 人（18.3%），比 P6（5 人）多一倍——**越高级人越多**，典型职级通胀。
再看 P7 分布在哪些部门：

```bash
dtool query --rows --sql "
  SELECT 部门, 姓名, 职级, 月薪 FROM hr WHERE 职级 = 'P7' ORDER BY 月薪 DESC LIMIT 5"
```

```json
{"部门":"人事部","姓名":"陈磊","职级":"P7","月薪":45900}
{"部门":"技术部","姓名":"陈洋","职级":"P7","月薪":45800}
{"部门":"技术部","姓名":"王霞","职级":"P7","月薪":45700}
```

**读法**：人事部也挂着 P7（4.59 万），说明**职级通道没分开**（技术序列的 P 级套到职能岗上）。
不解决这个，调薪和晋升永远说不清依据。

## ★ 工号是文本：前导零没丢

```bash
dtool query --rows --sql "SELECT 工号, 姓名, 部门 FROM hr ORDER BY 入职日期 DESC LIMIT 3"
```

```json
{"工号":"00136","姓名":"杨勇","部门":"销售部"}
{"工号":"00150","姓名":"赵静","部门":"产品部"}
{"工号":"00101","姓名":"李伟","部门":"技术部"}
```

**读法**：`00136` 没有被转成 `136`——转换阶段「带前导零的数字串保持文本」的规则在起作用。
这类字段（工号、身份证、银行账号）一旦变成数字，JOIN 和对外导出都会出错。

## ★★ 待评估名单：绩效为空 ≠ 不合格

```bash
dtool query --rows --sql "
  SELECT 工号, 姓名, 部门, 职级, 入职日期 FROM hr
  WHERE 绩效 IS NULL ORDER BY 入职日期"

dtool query --format xlsx --output out/待评估名单.xlsx --sql "
  SELECT 工号, 姓名, 部门, 职级, 入职日期 FROM hr WHERE 绩效 IS NULL ORDER BY 入职日期"
```

```json
{"工号":"00118","姓名":"赵明","部门":"市场部","职级":"P4","入职日期":"2026-02-18"}
{"工号":"00132","姓名":"陈艳","部门":"人事部","职级":"P4","入职日期":"2026-03-10"}
{"工号":"00101","姓名":"李伟","部门":"技术部","职级":"P4","入职日期":"2026-05-05"}
{"工号":"00150","姓名":"赵静","部门":"产品部","职级":"P5","入职日期":"2026-05-20"}
{"工号":"00136","姓名":"杨勇","部门":"销售部","职级":"P5","入职日期":"2026-09-21"}
```

**读法**：5 人全是 2026 年入职，最早 2 月、最晚 9 月。所以要区分两件事：
**2–5 月入职的 4 人该在本季度补评**；9 月入职的杨勇还在试用期，不该催。

## ★★ 部门 × 职级：一张透视表

```bash
dtool query --rows --sql "
  SELECT 部门,
         COUNT(*) FILTER (WHERE 职级 IN ('P3','P4')) AS 初级,
         COUNT(*) FILTER (WHERE 职级 IN ('P5','P6')) AS 中级,
         COUNT(*) FILTER (WHERE 职级 = 'P7') AS 高级
  FROM hr GROUP BY 1 ORDER BY 1"
```

```json
{"部门":"产品部","初级":2,"中级":6,"高级":1}
{"部门":"人事部","初级":5,"中级":1,"高级":1}
{"部门":"市场部","初级":3,"中级":3,"高级":0}
{"部门":"技术部","初级":5,"中级":5,"高级":4}
{"部门":"财务部","初级":3,"中级":4,"高级":2}
{"部门":"销售部","初级":7,"中级":5,"高级":3}
```

**读法**：技术部 4 名高级（28.6%），是唯一「高级占比合理」的部门；人事部 5 初级 1 中级
却有 1 高级，**中间断层**——梯队不连续，晋升路径没法讲。

## ★★★ 各部门薪酬 Top2（窗口函数）

```bash
dtool query --rows --sql "
  SELECT 部门, 姓名, 月薪 FROM (
    SELECT 部门, 姓名, 月薪,
           ROW_NUMBER() OVER (PARTITION BY 部门 ORDER BY 月薪 DESC) AS r
    FROM hr) WHERE r <= 2 ORDER BY 部门, 月薪 DESC"
```

```json
{"部门":"产品部","姓名":"赵涛","月薪":42000}
{"部门":"产品部","姓名":"杨艳","月薪":23900}
{"部门":"人事部","姓名":"陈磊","月薪":45900}
{"部门":"人事部","姓名":"吴勇","月薪":33900}
{"部门":"市场部","姓名":"王磊","月薪":24900}
{"部门":"市场部","姓名":"吴勇","月薪":23000}
```

**读法**：注意 **「吴勇」出现两次**（人事部 3.39 万 / 市场部 2.3 万）——同名不同人。
所以**姓名不能当主键**，一律用工号。

## ★★ 绩效分布：先看盘子再谈激励

```bash
dtool query --rows --sql "
  SELECT COALESCE(绩效,'未评') AS 绩效, COUNT(*) AS 人数
  FROM hr GROUP BY 1 ORDER BY 1"
```

```json
{"绩效":"A","人数":9}
{"绩效":"B","人数":31}
{"绩效":"C","人数":15}
{"绩效":"未评","人数":5}
```

**读法**：已评 55 人里 A 占 16.4%、C 占 27.3%——**C 比 A 多**，说明考核偏严或标准漂移。
按 60 人、A 目标 20% 算，A 应有 12 人；现在 9 人，补评 5 人后至少还要再上浮 3 个。

## HR 周报结论（可直接抄）

1. 全公司月薪合计 **143.4 万**（年化 1721 万）；技术部 37.4 万最高，市场部 6 人 / 12.2 万最「小而贵」。
2. **职级通胀**：P7 共 11 人（18.3%）多于 P6（5 人），且人事部也挂 P7——职级通道需要拆开（技术/职能双序列）。
3. 待评估 5 人全部是 2026 年入职；其中 **9 月入职的杨勇在试用期**，本季度只催 2–5 月的 4 人。
4. 绩效 A 16.4% / C 27.3%，C 多于 A；按 60 人、A 目标 20% 算应有 12 人，现 9 人。
5. 梯队：技术部 4 名高级结构合理；**人事部 5 初级 + 1 高级缺中级**，晋升断档。

## 常见坑

- **`COUNT(*) FILTER (WHERE ...)` 是 DuckDB 语法**；SQLite 用
  `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`。两者结果一样，别混着抄。
- **`AVG` 别套 `AVG`**：部门平均再平均 ≠ 全公司平均，人数不同权重就不同。
- **`绩效 IS NULL` 不是 `绩效 = NULL`**：后者永远为空结果。
- **姓名可能重复**（本数据就有两个「吴勇」）：`JOIN`/去重一律用 `工号`。
- **工号是文本**：如果哪天它在某张表里被读成数字，`00101` 会变成 `101`，跨表 JOIN 就对不上。
- **`ROW_NUMBER()` 的并列**：月薪相同时顺序不稳定，要确定性就加第二排序键（如工号）。

## 完整命令清单

```bash
dtool convert --input hr.xlsx --sheet 员工 --name hr

dtool query --sql "SELECT 部门, COUNT(*) 人数, ROUND(AVG(月薪)) 平均月薪, ROUND(SUM(月薪)) 月薪总额 FROM hr GROUP BY 1 ORDER BY 2 DESC"
dtool query --sql "SELECT 职级, COUNT(*) 人数, ROUND(AVG(月薪)) 平均月薪 FROM hr GROUP BY 1 ORDER BY 1"
dtool query --sql "SELECT 工号, 姓名, 部门, 职级, 入职日期 FROM hr WHERE 绩效 IS NULL ORDER BY 入职日期"
dtool query --sql "SELECT 部门, COUNT(*) FILTER (WHERE 职级 IN ('P3','P4')) 初级, COUNT(*) FILTER (WHERE 职级 IN ('P5','P6')) 中级, COUNT(*) FILTER (WHERE 职级='P7') 高级 FROM hr GROUP BY 1 ORDER BY 1"
dtool query --sql "SELECT COALESCE(绩效,'未评') 绩效, COUNT(*) 人数 FROM hr GROUP BY 1 ORDER BY 1"
dtool query --format xlsx --output out/待评估名单.xlsx --sql "SELECT 工号, 姓名, 部门, 入职日期 FROM hr WHERE 绩效 IS NULL"
```
